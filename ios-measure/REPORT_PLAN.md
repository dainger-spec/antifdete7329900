# Сроки до первой версии и риски (черновик, уточняется по замерам)

## Что входит в первую версию

Это предложение; объём утверждает владелец.

1. Сессии. Каждая сессия — своё `WKWebsiteDataStore(forIdentifier:)`, вкладки, адресная строка, история. Список сессий: создать, переименовать, удалить, экспортировать и импортировать куки.
2. Прокси на сессию: HTTP и SOCKS5 с паролем, без отката на прямое соединение. При добавлении — проверка: выходной IP, страна, работает ли.
3. Часовой пояс сессии по стране прокси. Это готовая правка из `PrivacyScripts`. Язык — по итогам замера `q2.language-at-runtime`.
4. Отпечаток: строка UA из готовых вариантов, канвас, WebGL и звук (выключить, настоящий, шум), переключатель WebRTC.
5. Доступ (решение владельца, 8 ноября, вторая версия): покупки через Apple нет. Вход аккаунтом Lumen; что
   доступно — решает подписка (подписанный документ прав сервера, как на Mac). Экран подписки: тариф, счётчик
   профилей, тарифы с составом; кнопка апгрейда открывает сайт во внешнем браузере. Истёкшая подписка — окно и
   блокировка действий, данные сохраняются. Без входа — бесплатный уровень: два профиля без прокси, полная
   изоляция и подмена. iPhone не занимает место устройства, профили — в общем лимите лицензии с Mac.
   Позиционирование: браузер изолированных сессий для тестирования; слов «антидетект», «обход», «фингерпринт»,
   «подмена отпечатка», «мультиаккаунт» нет ни в интерфейсе, ни в Info.plist. План Б, если откажут: покупка
   через Apple, права — из того же документа. (3.1.3(b) по букве требует покупки и в приложении; владелец
   решил по живым приложениям категории, которые так работают.)
   Профиль, живший за прокси, при потере доступа заперт и никогда не открывается напрямую.
6. Проверки утечек в CI на симуляторе: стенд `ios-measure` превращается в регрессионный набор.

## Оценка (рабочие недели одного разработчика, знакомого с кодом macOS-версии)

| Часть | Недели | Почему столько |
|---|---|---|
| Оболочка браузера: сессии, вкладки, адресная строка, интерфейс | 2–2,5 | новый UIKit/SwiftUI; из macOS-кода переносится только ядро (BrowserCore) |
| Прокси, проверка, часовой пояс и язык | 1 | API проверено замером; ProxyConfigurationFactory и проверка прокси есть в macOS-коде |
| Отпечаток и его проверки на устройстве | 2 | фикстура q2 → продуктовый код; закрыть каналы, найденные замером (воркеры, фреймы, стек) |
| Вход и права, бесплатный уровень | 1 | документ прав и решение — из кода Mac; сервер: iPhone как устройство, аккаунт для ревью без кода из письма. Покупка через Apple — только по плану Б (+1) |
| Регрессия утечек в CI и прогоны на iPhone | 1 | стенд уже есть |
| Подготовка к ревью, ответы рецензенту | 1–2 (календарно) | исход непредсказуем |
| **Итого до первой версии в App Store** | **8–9,5** | без Telegram (−0,5); с покупкой через Apple по плану Б — +1 |

## Решения владельца (8 ноября)

- **Telegram (q3) из плана убран.** Антидетект важнее: `WKAppBoundDomains` не объявляется, подмена работает на
  всех сайтах. Цена: в веб-видах приложения нет service workers, и Telegram Web полноценно работать не будет (в
  обычной сборке service worker не регистрируется; с App-Bound Domains регистрируется, но тогда пользовательский
  скрипт не выполняется нигде, кроме доменов списка — `REPORT.md`, раздел 3, прогоны 42422628437 и 42423975642).
  Замеры q3 остаются в `REPORT.md` как основание решения.
- **Подмена — полная по умолчанию** (как на Mac: сначала то, что задаёт сам WebKit, затем скрипт), с
  переключателем на упрощённую.
