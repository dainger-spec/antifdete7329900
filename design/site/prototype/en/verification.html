How we verify

Every build, against real Safari

We do not ask you to take our word for it. Every change to Lumen is built on a Mac with real Safari: a profile is compared with it, every request around the proxy is looked for, and the results are recorded. Leak checks

Separate checks run a profile behind real proxies on the CI machine and look for any way around them. A check fails at the first request that goes around.

QUIC and HTTP/3
stays on the proxy

Without a proxy, cloudflare-quic.com answers a profile over HTTP/3; through an HTTP or SOCKS5 proxy, over HTTP/2, and the proxy sees every request. UDP is never even asked of the proxy.

leak_check · every build

WebRTC
off in a proxied profile

No RTCPeerConnection in the page, its frames or its workers. A control without a proxy does get its public address over STUN — so the check sees a leak when there is one.

leak_check and the self-test

DNS
never around the proxy

The test page asks for names to be resolved early: dns-prefetch, preconnect, a Link header. The packet capture holds no DNS question for any of them.

egress_check

Requests to the computer itself
refused

A page, a frame and a worker reach for 127.0.0.1, localhost, ::1 and 0.0.0.0. Each request is refused; a loopback listener takes no connection.

self-test

Certificates
refused at the handshake

A test server presents a certificate the system would go to the network to complete. In a proxied profile it is refused at the handshake — through the proxy.

self-test

Every packet off the machine
none around the proxy

While a profile opens a page that makes every kind of request, CI records every packet leaving the machine with the process that sent it: 2,410 packets in the latest run.

egress_check · pktap

Writes to disk
nothing in Safari’s folders

Every write of the app and WebKit is traced: a profile writes nothing where the real Safari keeps its data. In the latest run, a trace of 606,017 lines.

disk_check · fs_usage

Safari’s services
never called

Search suggestions, Safe Browsing, translation, Apple Pay and the other services that go to the network from processes of their own are not called from a profile’s process: connections to them are refused.

self-test and packet capture

Check it yourself

All you need is your Mac and any proxy.

  1. The address

    In a profile with a proxy, open a page that shows your IP address. It must be the proxy’s.

  2. Fail-closed

    Switch the proxy off and reload. The page must not open — let alone show your real address.

  3. The fingerprint

    Open the same fingerprint test page in Safari and in a profile on this Mac. The values match — apart from Apple Pay and Web Push.

If the test page says “Canvas: Spoofed”, open it in plain Safari 26: deviceinfo.me says the same there. Its test knows only an older PNG length, and today’s WebKit encodes the same picture differently.
