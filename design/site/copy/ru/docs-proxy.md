## Какие прокси подходят

SOCKS5 и HTTP — с логином и паролем или без них. HTTPS — это HTTP-прокси, соединение с которым шифруется TLS **Не подтверждено:** работа через HTTPS-прокси тестами не проверена.

## Где задать прокси

В редакторе профиля (**⋯ → Изменить…**, часть **Соединение**) у поля **Подключение** три кнопки: **Без прокси**, **Из списка** и **Новый**. Выберите **Новый** и вставьте прокси одной строкой, как его дал провайдер: `хост:порт:логин:пароль`, `логин:пароль@хост:порт`, `socks5://логин:пароль@хост:порт` или `хост:порт`. Схема задаёт тип: `socks5://` (или `socks5h://`, `socks://`), `http://`, `https://`.

Без схемы тип находит проверка — кнопка **Проверить** или **Сохранить**; без найденного типа прокси не сохраняется.

Поле **Домены в обход (через запятую)** исключает домены из прокси **Не подтверждено:** уходят ли они напрямую, с адреса этого Mac, — не измерено. Изменения действуют со следующего запуска. Подробнее — в статье о создании профиля.

## Список и проверка

Список — в боковой панели окна профилей, пункт **Прокси**; он зашифрован и хранится только на этом Mac. У каждого профиля своя копия прокси.

- **Добавить** — один прокси той же строкой; **Импорт…** — целый список, вставкой или **Из файла…**, по прокси в строке. Текст после `#` становится названием. Нечитаемые строки перечислены с номером и причиной; повтор (тот же хост, порт и логин) пропускается. Тип строк без схемы по умолчанию находит первая проверка; до неё они профилям не назначаются.
- **Назначить профилям…** — один прокси всем отмеченным профилям или несколько по очереди, по кругу. Запущенный профиль работает со своим прокси до остановки.
- **⋯ → Изменить…** — правка доходит до профилей с этим прокси. **⋯ → Экспорт…** сохраняет логины и пароли открытым текстом.

**Проверить все** и **Проверить выбранные** проверяют каждый прокси через него самого, по шагам: **Адрес**, **Соединение**, **Рукопожатие** SOCKS5 и HTTP, **Логин**, **Туннель**, затем **Через прокси** — запрос к сервису геолокации. Напрямую — никогда. У работающего прокси видны страна, город, внешний IP, сеть и задержка — медиана трёх туннелей, у выбранного — отчёт по шагам и **Что делать**. Проверки идут только по вашей просьбе.

## Часовой пояс и язык

При запуске профиль спрашивает через прокси сервис геолокации (ipinfo.io, затем geojs.io, ipwho.is и ipapi.co) — тот видит адрес прокси, а не этого Mac. Из ответа профиль берёт часовой пояс места выхода, а по стране — язык для сайтов, например `de-DE` для Германии. Так работает **Часовой пояс и язык → Из подключения** (часть **Место и язык**, по умолчанию).

Ответа ждут до трёх секунд, а если место выхода известно — до секунды. Не ответил ни один сервис — профиль берёт пояс и язык прошлого запуска или этого Mac, и Lumen об этом пишет. Если выключено **Профили — отдельными приложениями в Dock**, язык на весь сеанс задаёт первый запущенный профиль. Для прокси с ротацией есть **Предупреждать, если IP прокси сменился**.

## DNS, WebRTC и UDP

- **DNS.** Имена сайтов разрешает прокси: и SOCKS5, и HTTP-прокси получают имя, а не адрес. Этот Mac ищет только адрес самого прокси. Предзагрузка DNS заблокирована.
- **WebRTC** с прокси выключен при любой настройке: его UDP ушёл бы мимо прокси.
- **QUIC (HTTP/3)** с прокси не используется — страницы идут через прокси по HTTP/2. Профилю в своём процессе система не даёт отправлять UDP.
- **Адреса этого Mac** (`127.0.0.1`, `localhost`) страницам закрыты; адреса локальной сети уходят через прокси — в его сеть.

Из настроек мимо прокси ведут только **Домены в обход (через запятую)** и **Safe Browsing (запросы идут в обход прокси)**; по умолчанию оба не действуют. Синхронизация и проверка обновлений идут напрямую: это соединения приложения, а не профилей.

В последнем зарегистрированном прогоне CI из 2 410 пакетов, записанных во время самотеста, ни один не ушёл мимо прокси **Не подтверждено:** замер — с тестовыми прокси на том же Mac, удалённый прокси не измерялся.

## Если прокси не работает

Пока прокси не отвечает, страницы профиля не загружаются: прямым соединением Lumen прокси не заменяет. Самотест в CI проверяет это с недоступным прокси и с прокси, чьё имя не находится.

**Не запускается.** Если адрес прокси нельзя применить или HTTP-прокси требует логин, которого у профиля нет (это видно, когда запуск узнаёт место выхода), профиль не запускается: «…Профиль не запущен…» **Не подтверждено:** по коду профиль в своём процессе этого сообщения не показывает. Если это выяснилось уже после открытия окна, профиль останавливается.

**Запущен, но прокси не работает.** При запуске Lumen один раз спрашивает сам прокси; если он не работает, окно профилей выходит вперёд: **«…» не загружает страницы**, отчёт по шагам, **Проверить прокси** и **Показать в «Прокси»**. Пункт **Не запускать профиль** (**Настройки → Прокси → Если прокси не работает**) оставляет такой профиль остановленным; по умолчанию — **Запускать профиль и говорить почему**.

**Отказал во время работы.** Страницы перестают загружаться, в окне приложения — **Не удалось загрузить страницу** и причина **Не подтверждено:** что в этом случае показывает окно Safari. Окно профилей молчит: прокси спрашивается только при запуске.

| Состояние | Что делать |
| --- | --- |
| **Хост не найден** | Проверьте адрес на опечатку |
| **Соединение отклонено** | Проверьте порт; если он верен, служба прокси остановлена |
| **Молчит после соединения** | Добавьте IP этого Mac в белый список провайдера или переключите прокси на вход по логину |
| **Нужен логин**, **Логин отклонён** | Скопируйте логин и пароль из кабинета провайдера |
| **Отказывает этому Mac** | Прокси привязан к IP: добавьте IP этого Mac у провайдера |
| **Нет выхода в сеть** | Проверьте позже или напишите провайдеру |
| **Подменный DNS VPN** | Проверьте прокси с выключенным VPN |

Чтобы вернуть профиль, нажмите **Проверить прокси**. Заработал — обновите страницу, а если проверка исправила тип, откройте профиль заново. Нет — исправьте прокси (**⋯ → Изменить…**) или назначьте другой и перезапустите профиль. Другие сбои — в статье что делать, если что-то не работает.
