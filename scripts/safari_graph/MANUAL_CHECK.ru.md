# Ручная проверка SAFARI_GRAPH на Mac с включённым SIP

Проверка отвечает на вопрос спайка (`docs/SAFARI_GRAPH_SPIKE.md`): загружается ли системный
`Safari.framework` в процесс стороннего приложения и поднимается ли его интерфейс.

**Зачем она нужна, если есть CI.** На macOS-раннерах GitHub SIP выключен (`csrutil status`:
disabled; это видно в логе каждого прогона). Поэтому CI показывает верхнюю границу: всё, что не
загрузилось там, не загрузится и на обычном Mac. Если же что-то загрузилось в CI, это ещё не значит,
что оно загрузится при включённом SIP. Ответ для обычного Mac даёт только эта проверка.

## Что нужно

- macOS 14 или новее, обычная учётная запись. Права администратора не нужны.
- Command Line Tools: `xcode-select --install`. Для режима `--build` нужен Xcode или Command Line
  Tools со Swift, как для обычной сборки приложения (`scripts/build-app.sh`).
- **SIP не выключать.** Проверка нужна именно с включённым SIP.

## Что скрипт делает и чего не делает

- Не меняет ничего в системе: не трогает SIP и настройки безопасности, не просит `sudo`, ничего не
  устанавливает.
- Собирает маленькую программу-пробу (`scripts/safari_graph/probe.m`) в папку `build/` репозитория и
  подписывает её локально (ad hoc): без исключений hardened runtime и с каждым исключением по очереди.
  Каждый вариант пытается загрузить (`dlopen`) WebKit, SafariServices, служебные фреймворки Safari и
  сам `Safari.framework`, записывает ответ системы и завершается.
- Каждый вариант запускается дважды: как есть и с `DYLD_VERSIONED_FRAMEWORK_PATH`, указывающим на
  «staged»-фреймворки Safari в системном криптексе (так сам Safari получает свои версии WebKit и
  служебных фреймворков). Ещё два прогона используют пробу, в которую этот путь вшит при сборке.
  Переменная задаётся только запускаемой пробе, системные настройки не меняются.
- Окно и интерфейс Safari проба по умолчанию **не** открывает. С ключом `--with-ui` (см. ниже), если
  `Safari.framework` загрузился, она пробует поднять интерфейс Safari внутри себя. Код Safari при этом
  получает временную домашнюю папку внутри `build/`, поэтому ваши история, закладки и данные сайтов
  Safari не затрагиваются. Но этот код может обратиться к связке ключей или iCloud вашей учётной
  записи, поэтому ключ нужен только по желанию. В CI этот шаг выполняется всегда.
- С `--build` (или `--app`) запускает ещё self-test нового режима. Он открывает два окна на несколько
  секунд и работает со временным хранилищем, которое удаляется сразу после проверки. Ваши профили и
  данные он не трогает.

## Шаги

1. Взять ветку:
   ```sh
   git fetch origin claude/safari-graph-spike
   git checkout claude/safari-graph-spike
   ```
2. Убедиться, что SIP включён:
   ```sh
   csrutil status
   ```
   Должно быть `System Integrity Protection status: enabled.`
3. Запустить пробу (около минуты):
   ```sh
   scripts/safari_graph/manual_check.sh
   ```
4. По желанию то же самое со сборкой приложения и self-test нового режима (5–10 минут):
   ```sh
   scripts/safari_graph/manual_check.sh --build
   ```
   Если у вас уже есть сборка с `SANDBOX=0`, можно указать её:
   `scripts/safari_graph/manual_check.sh --app путь/к/PrivacyBrowser.app`.
   Попытку поднять интерфейс Safari добавляет ключ `--with-ui` (его смысл и оговорка описаны выше).
   Ключи можно сочетать: `manual_check.sh --build --with-ui`.
5. Прислать архив, путь к которому скрипт печатает в конце:
   `build/safari-graph-manual-<дата>.zip`.

## Как читать итог

Скрипт печатает сводку, по строке на каждый прогон. Пример:

```
base  safari_framework_loaded=no  exit=0
dyld+env  safari_framework_loaded=yes  exit=0
```

- Первое слово — какой прогон:
  - `base`: без исключений hardened runtime;
  - `libval`: `com.apple.security.cs.disable-library-validation`;
  - `dyld`: `com.apple.security.cs.allow-dyld-environment-variables`;
  - `jit`: `com.apple.security.cs.allow-jit` и `allow-unsigned-executable-memory`;
  - `all`: все перечисленные вместе плюс `disable-executable-page-protection`;
  - суффикс `+env`: тот же вариант с `DYLD_VERSIONED_FRAMEWORK_PATH` на staged-фреймворки Safari;
  - `linked-base`, `linked-dyld`: проба, в которую этот путь вшит при сборке (`LC_DYLD_ENVIRONMENT`),
    без исключений и с исключением `dyld`;
  - суффиксы `-window` и `-safari-main` (только с `--with-ui`): попытка открыть окно Safari и запуск
    собственной точки входа Safari в первой конфигурации, где фреймворк загрузился.
- `safari_framework_loaded`: загрузился ли сам `Safari.framework` в процесс пробы.
- `safari_main_windows`: какие окна поднялись (заголовок, класс, видимо ли окно).
- `exit`: код завершения. 0 — проба отработала. 43 — проба сама остановила интерфейс Safari после
  20 секунд наблюдения. 134 или 139 — процесс аварийно завершился внутри кода Safari, это тоже
  результат.

Ниже идут дословные причины, по которым `dlopen` не загрузил `Safari.framework`. Это текст системы.
Например, `Symbol not found: …` означает несовпадение версий: проба связала Safari.framework с
базовыми системными версиями служебных фреймворков, а ему нужны его собственные. `… not valid for use
in process …` или `… disallowed by system policy` означают отказ политики подписи кода.
Если есть self-test, в конце видны решение «шлюза совместимости» приложения
(`safari-graph: gate on this Mac: …`) и итог `SAFARI-GRAPH SELFTEST PASSED/FAILED`.

## Что означает результат

- **`safari_framework_loaded=no` во всех прогонах.** На этом Mac `Safari.framework` в наш процесс не
  загружается ни в одной конфигурации. Приложение в этом случае автоматически остаётся на своём
  WKWebView-интерфейсе.
- **`yes` только в прогонах `+env` или `linked-…`.** Загрузка возможна лишь тогда, когда процесс берёт
  staged-фреймворки Safari. Первый такой прогон показывает минимально необходимое исключение.
- **`yes` уже в `base`.** Исключения не нужны. Следующий вопрос в том, поднимается ли интерфейс
  (запуск с `--with-ui`).
- **Код 134 или 139.** Фреймворк загрузился, но аварийно остановил процесс при собственных проверках.
  Это тоже результат, его нужно прислать.

## Где лежат файлы

`build/safari-graph-manual-<дата>/`:

- `sip.txt`: состояние SIP;
- `facts.txt`: где лежит Safari, что он подключает, его подпись и ключи entitlements;
- `probe/probe.log`: полный журнал пробы; `probe/run-<прогон>.log`: журнал каждого прогона;
  `probe/summary.txt`: короткая сводка; `probe/safari-main-home/`: что код Safari записал во временную
  домашнюю папку (только с `--with-ui`);
- `selftest.log` и `surface/`: self-test нового режима и снимок поверхности профиля (если запускался).
