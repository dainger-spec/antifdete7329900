# PrivacyBrowser

Приложение для macOS, в котором работа, личное и каждый клиент живут в отдельных профилях.
Каждый профиль — отдельный браузер на настоящем WebKit (тот же движок, что у Safari) со своими
cookies, данными сайтов, историей, закладками, паролями и, при желании, своим прокси.
Данные профилей хранятся на диске зашифрованными под мастер-паролем.

Интерфейс — на русском (английский запасной), светлый нативный стиль, тёмная тема по желанию.

> Это не «антидетект» и не эмулятор других устройств. Профили изолированы по данным и по сети,
> но все они работают на одном и том же Mac, и сайт, который снимает отпечаток устройства, это
> видит. Честные ограничения — ниже и в [docs/ISOLATION_AND_LIMITATIONS.md](docs/ISOLATION_AND_LIMITATIONS.md).

## Что умеет

**Профили**
- Создать, переименовать, дублировать (те же настройки и закладки, данные — с нуля), удалить.
- Открыть в один клик из боковой панели; несколько профилей работают одновременно.
- Полная изоляция: cookies, localStorage, sessionStorage, IndexedDB, Cache API, service workers,
  HTTP-кэш, HSTS — у каждого профиля свои (`WKWebsiteDataStore(forIdentifier:)`).
  Проверяется self-test’ом на настоящем WebKit.
- Временный профиль: ничего не пишется на диск, всё забывается при закрытии.
- Вкладки, оставшиеся открытыми, восстанавливаются при следующем открытии профиля
  (хранятся зашифрованными; фоновые вкладки загружаются, только когда вы на них переключитесь).

**Сеть**
- Прокси на профиль: HTTP (CONNECT), HTTPS-прокси (TLS до прокси), SOCKS5 и socks5h, с логином и
  паролем. Адрес вставляется одной строкой: `socks5://user:pass@203.0.113.5:1080`,
  `http://host:8080`, `host:port`, `host:port:user:pass`.
- Имена сайтов разрешает прокси (SOCKS5 отправляет имя хоста, как socks5h; проверено self-test’ом).
- Если прокси не отвечает, страницы не грузятся — профиль никогда не уходит в обход прокси.
- Без прокси профиль просто работает через обычную сеть этого Mac.
- **Единый выход для TCP и UDP (по желанию).** Обычный прокси на macOS закрывает только TCP:
  QUIC/HTTP3 и WebRTC идут по UDP мимо прокси и раскрывают ваш IP. Переключатель «Единый выход»
  поднимает на профиль локальный туннель (Network Extension), через который идёт весь трафик, так
  что TCP и UDP выходят с одного IP. Если туннель включён, но не поднялся — профиль остаётся без
  сети (fail-closed), не выходит напрямую. Туннель off по умолчанию и требует подписанной сборки
  (`NE=1`); без него держите WebRTC выключенным. Подробно: [docs/NETWORK.md](docs/NETWORK.md).
- Индикатор прокси в боковой панели и в окне браузера: без прокси / работает / не работает;
  кнопка «Проверить прокси».

**Данные**
- Импорт и экспорт cookies: Netscape `cookies.txt` и JSON (формат расширений Cookie-Editor /
  EditThisCookie). HttpOnly-cookies сохраняются.
- Экспорт и импорт профиля одним файлом `.pbbackup`: настройки, cookies и данные сайтов,
  история, закладки, пароли. Файл шифруется отдельным паролем и открывается на другом Mac.
- Шифрование на диске: AES-256-GCM, ключ из мастер-пароля (PBKDF2-HMAC-SHA256, 600 000 итераций),
  отдельный ключ у каждого профиля. Данные сайтов закрытого профиля лежат только в
  зашифрованном архиве.

**Браузер**
- Вкладки (⌘T, ⌘W, ⇧⌘T, ⌃⇥, ⌘1…⌘9), назад/вперёд, обновить, адресная строка с поиском,
  индикатором загрузки и значком защищённого соединения.
- Закладки (⌘D, папки, перетаскивание) и история (⌘Y, поиск, очистка, срок хранения) —
  свои у каждого профиля, зашифрованы.
- Загрузки — в свою папку у каждого профиля: `~/Downloads/PrivacyBrowser/<профиль>/`
  (список загрузок: ⌥⌘L).
- User-Agent на профиль: «Safari для Mac» (по умолчанию — ровно тот UA, что у Safari на этом
  Mac), «Safari для iPhone/iPad — только User-Agent» (мобильные версии сайтов), или свой.
- Язык сайтов и часовой пояс на профиль.
- Сохранённые пароли с подстановкой, ответы на HTTP Basic/Digest.

**Надёжность**
- Закрытие окна, переключение профилей и неработающий прокси не роняют приложение
  (проверяется self-test’ом).
- Ошибки — человеческим языком: «Прокси не отвечает», «Сайт не найден», «Нет подключения
  к интернету»… Технический код — мелко, для отчёта об ошибке.
- Журнал в файл (`~/Library/Logs/PrivacyBrowser`, в песочнице — внутри контейнера):
  **Справка ▸ Показать журнал** или **Настройки ▸ Журнал**. В журнал не попадают адреса
  страниц, cookies, пароли и названия профилей.

## Сборка

Нужны macOS 14 Sonoma или новее и Xcode 15+ (или Command Line Tools со Swift 5.9+).

```bash
scripts/build-app.sh                  # сборка с App Sandbox → build/PrivacyBrowser.app
open build/PrivacyBrowser.app

SANDBOX=0 scripts/build-app.sh        # без песочницы (для отладки)
APP_DIR=build/other scripts/build-app.sh
BUNDLE_ID=org.example.PrivacyBrowser SIGN_IDENTITY="Developer ID Application: …" scripts/build-app.sh
```

- Запускайте `.app`, а не `swift run`: WebKit называет свои каталоги по bundle identifier, а
  песочнице нужен подписанный бандл.
- По умолчанию сборка — в App Sandbox; данные лежат в `~/Library/Containers/<bundle-id>/Data/`.
- Ad-hoc подписи достаточно для запуска у себя. Для распространения подпишите Developer ID и
  нотаризуйте.
- `PRIVACYBROWSER_LANG=en` — английский интерфейс. `PRIVACYBROWSER_VAULT_DIR=/путь` — другое
  хранилище (для разработки).

### Тесты

```bash
swift test                                        # ядро (BrowserCore) — также на Linux в CI
TZ=America/New_York node scripts/test-shims.mjs   # JS-скрипты профиля (Node 18+)

# Проверка на настоящем WebKit этого Mac (без окон, во временном хранилище):
python3 scripts/selftest_proxy.py --http 18080 --socks 18081 &
PB_SELFTEST_HTTP_PROXY_PORT=18080 PB_SELFTEST_SOCKS_PROXY_PORT=18081 \
  build/PrivacyBrowser.app/Contents/MacOS/PrivacyBrowser --self-test
```

CI (`.github/workflows/ci.yml`) на каждый push: тесты ядра на Linux и macOS, тесты
JS-скриптов, сборка с песочницей и без, self-test на настоящем WebKit для обеих сборок
(изоляция, шифрование, прокси, вкладки, cookies, экспорт/импорт профиля, восстановление
вкладок, жизненный цикл окон) и проверка миграции в контейнер песочницы.

## Как пользоваться

1. При первом запуске — короткое знакомство и создание мастер-пароля. Восстановить его нельзя.
2. **＋** — новый профиль: название, стартовая страница, прокси (вставьте адрес и нажмите
   «Проверить прокси»), язык и часовой пояс сайтов, User-Agent, WebRTC, геолокация, история.
3. Кнопка ▶ в строке профиля (или «Открыть» на его странице) открывает окно браузера.
   Каждое окно и вкладка подписаны названием профиля. Закрытие последнего окна сохраняет
   вкладки, шифрует данные профиля и возвращает к списку профилей.
4. Меню профиля (правый клик в боковой панели или страница профиля): настройки,
   переименовать, дублировать, импорт/экспорт cookies, экспорт профиля, пароли, удалить.
   Импорт профиля — кнопка ＋ (удерживать) или **Файл ▸ Импортировать профиль…**.
5. **Заблокировать** закрывает все профили, шифрует их данные и забывает ключи. ⌘Q делает то же
   и ждёт, пока всё будет зашифровано.
6. **Настройки (⌘,)**: оформление (светлое, тёмное, как в системе), мастер-пароль,
   синхронизация (необязательно), журнал.

## Честные ограничения

- **Общее железо Mac.** Все профили работают на одном Mac и одном WebKit: шрифты, экран,
  видеокарта (WebGL, отрисовка canvas), число ядер, TLS-отпечаток и заголовок
  `Accept-Language` у них одинаковые. Сайт, который снимает отпечаток устройства, может понять,
  что два профиля открыты на одном компьютере, даже если у них разные cookies и IP.
  Изоляция — по данным и по сети, а не по «железу».
- **Режим iPhone/iPad меняет только строку User-Agent.** Сайты покажут мобильную вёрстку, но
  браузер остаётся Safari на Mac: размер экрана, шрифты, графика, сенсорный ввод, набор функций
  движка. Это не эмуляция iPhone, и любой сайт, который проверяет больше одной строки, это видит.
- **Язык, часовой пояс, геолокация, WebRTC** задаются скриптами на странице: в worker’ах их
  нет, а заголовок `Accept-Language` WebKit берёт из языка приложения, одинакового для всех
  профилей.
- **WebRTC и QUIC по UDP не идут через обычный прокси** (платформенное ограничение
  `ProxyConfiguration` — проксируется только TCP). Для одного IP на TCP и UDP включите «Единый
  выход» (туннель, нужна сборка `NE=1`); иначе держите WebRTC выключенным (так по умолчанию).
  Датапас туннеля пока в состоянии каркаса (fail-closed) — см. [docs/NETWORK.md](docs/NETWORK.md)
  и `networkextension/`.
- **Пока профиль открыт, его данные сайтов лежат на диске незашифрованными** (WebKit не умеет
  шифровать их сам); они шифруются при закрытии. После сбоя — при следующей разблокировке.
- **Загрузки — обычные файлы** в `~/Downloads/PrivacyBrowser/…`, не шифруются и не удаляются
  вместе с профилем.
- **Экспорт cookies** — это открытый текст с активными входами на сайты; храните такой файл
  как пароль.
- Один сетевой процесс WebKit на всё приложение: изоляция — по сессиям внутри него, а не по
  процессам ОС.
- Безопасностный аудит не проводился.

Подробности и способы проверить каждое утверждение:
[docs/ISOLATION_AND_LIMITATIONS.md](docs/ISOLATION_AND_LIMITATIONS.md).
Устройство: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Синхронизация (необязательная):
[docs/SYNC_FORMAT.md](docs/SYNC_FORMAT.md), [docs/SYNC_SERVER_API.md](docs/SYNC_SERVER_API.md).

## Структура

```
Package.swift
Sources/
  BrowserCore/      ядро без UI, тестируется на macOS и Linux: шифрование, хранилище профилей,
                    пароли, история/закладки, сессии вкладок, cookies (форматы), прокси (URL),
                    экспорт/импорт профиля, журнал, понятные тексты ошибок, синхронизация
  PrivacyBrowser/   приложение macOS (SwiftUI + AppKit + WebKit)
    App/            точка входа, модель, настройки, журнал, self-test
    Browser/        сессия профиля, окно, вкладки, загрузки, cookies, прокси, скрипты страницы
    UI/             знакомство, мастер-пароль, профили (боковая панель + страница), редактор,
                    импорт/экспорт, настройки, библиотека
Tests/BrowserCoreTests/
Resources/          Info.plist, entitlements, ru/en строки
scripts/            build-app.sh, test-shims.mjs, selftest_proxy.py
docs/
```
